# مواصفة مسار التدريب (Lead → Talent Lab → Sales) + فجوات النظام الحالي

> **مصدر المطلب:** حزمة مواصفات من فريق التشغيل (2026).  
> **هدف الملف:** توثيق كامل لا يُنسى + مرجع لتنفيذ المراحل لاحقاً.  
> **ملاحظة تقنية:** «Salma / سلمى / سلوى» في النص التشغيلي = أشخاص/أدوار تشغيلية؛ في الكود الحالي لا يوجد دور باسم `Salma` — يُحدَّد لاحقاً (مثلاً `TrainingSalesCoordinator` أو مستخدم محدد).

---

## 1) تعريف الليد — التدريب

### من يراه
- مبيعات التدريب (`TrainingSales` وما يعادلها في النظام).
- Salma (حسب التعيين التشغيلي — ربط بدور/مستخدم).

### حقول إلزامية (مطلوب)
| حقل | ملاحظة |
|-----|--------|
| الاسم | |
| البريد | |
| الموبايل | |
| الجامعة / الكلية | |
| منطقة السكن | |
| المصدر | |
| السن **أو** تاريخ الميلاد | أحدهما أو كلاهما حسب القاعدة |
| هل متخرج أم لا | boolean / قائمة |

### الحالة في النظام الحالي (Flask / `app.py`)
- تسجيل الليد عبر `training_sales_register`: يحفظ **الاسم، الهاتف، البريد (اختياري)** فقط في `Candidates` مع `PrimaryIntent='Training'` و`Status='Training_Lead'`.
- **الفجوة:** لا توجد حقول إلزامية للجامعة، السكن، المصدر، العمر/تاريخ الميلاد، التخرج في النموذج أو الجدول (إلا إذا كانت موجودة عمودياً في `Candidates` ولم تُربط بالواجهة — يحتاج تدقيق مخطط DB عند التنفيذ).

## 2) نوعا الليد (مساران منفصلان)

### أ) Interested for training purposes (المسار الطبيعي)
- يدخل المسار العادي (مبيعات → اختبار تحديد مستوى → …).
- **لا يُسمح بحجز موعد لمختبر مواهب التدريب** إلا إذا كان **ظاهراً للمختبر** أن المرشح **دفع فاتورة اختبار تحديد المستوى** (أو حالة دفع معتمدة في النظام).

### ب) Train to Hire (Checkbox في رأس تعريف الشيت)
- عند التفعيل:
  - **إلزامي:** قائمة مستندات بروابط Google Drive (نص يسار + تسمية يمين):
    1. شهادة تخرج / إثبات قيد / إفادة جامعية  
    2. إيميل (بديل)  
    3. صورة بطاقة  
    4. إثبات تعاقد مع جهة توظيف  
  - **لا دفع ولا فاتورة** لهذا المسار لدخول المختبر.
  - يمر **مباشرة** إلى مختبر مواهب التدريب (بعد اكتمال المستندات — منطق التحقق يُعرّف عند التنفيذ).

### الحالة في النظام الحالي
- لا يوجد حقل `TrainToHire` أو ما يعادله في تسجيل الليد.
- حجز الموعد `training_sales_book_slot` **لا يتحقق** من وجود فاتورة امتحان (`InvoiceHeaders` / `exam fee`) قبل السماح بالحجز.
- **الفجوة:** مساران + قيود الدفع/المستندات غير مُنفَّذين.

## 3) مختبر مواهب التدريب (Talent Lab — Training context)

### أنواع الاختبارات (مطلوب — واجهة بأزرار واضحة)
1. **اختبار تحديد مستوى** — لمن دفع (Interested) **ولـ Train to Hire** (نفس نوع الاختبار الأول).
2. **اختبار دوري (مرحلي / Periodic)**
3. **اختبار تخرج (Exit / Graduation)**
4. **إعادة (Redo / RE_DO)** — عدم حضور/عدم إكمال في موعد سابق
5. **Exit Make-Up** — تعويض خروج

### الحالة في النظام الحالي
- في الكود: `exam_kind` لمسار الدفعة يدعم أساساً **`periodic`** و **`graduation`** (`_exam_kind_to_eval_type` → `Training_Periodic` / `Training_Graduation`).
- واجهات مثل `talent/dashboard.html` و `talent/exam_feedback.html` تعرض أزرار دوري/تخرج.
- **الفجوة:** لا يوجد تمييز صريح في الواجهة لخمسة أنواع أعلاه؛ Redo و Exit Make-Up كأزرار/أنواع تقييم منفصلة تحتاج نموذج بيانات + واجهة + حفظ في `Evaluations` (أو جدول مقابلات).

### Status بعد المقابلة (مطلوب)
| القيمة | معنى عربي (للعرض فقط) |
|--------|-------------------------|
| Accepted | مقبول |
| No Show | لم يحضر |
| Rejected | مرفوض |
| Resc | مُعاد جدولته |
| Pending | قيد الانتظار |
| Redo | إعادة |
| Unreachable | غير متاح |

### منطق القرار حسب النوع + الحالة (مطلوب)

**Accepted + Interested for training**  
→ قائمة/شيت **TO BE CLOSE** (متابعة مبيعات: إقناع، اشتراك، دفع، تحويل للـ Cooperation/التسجيل في دورة).

**Accepted + Train to Hire**  
→ قائمة **Acceptance Train to Hire** لـ: Salma، مديري التدريب، المحاسب.

**Rejected**  
→ لا إجراءات إضافية (إغلاق منطقي).

**Pending**  
→ مختبر اختبر لكن التقييم النهائي غير مكتمل → تاب **Pending** داخل مختبر التدريب.

**Resc / Redo / No Show**  
→ إرجاع لـ Salma/المبيعات لإعادة التواصل وحجز موعد جديد.

### الحالة في النظام الحالي
- صفحة التقييم `templates/talent/evaluate.html` تعرض قرارات محدودة: **Accepted / Training / Rejected** (ليست القائمة الكاملة أعلاه).
- لا توجد قوائم منفصلة: **TO BE CLOSE**، **Acceptance Train to Hire**، **Pending** كـ views مفلترة حسب `lead type + exam type + status`.
- **الفجوة:** توسيع القرارات، ربطها بمسار الليد، وworkflow التوجيه بين الأدوار.

### فلاتر على رؤوس الأعمدة
- **مطلوب:** كل كشوف المختبر تدعم فلترة أعمدة.
- **الحالة الحالية:** جزئي أو غير موحّد — يحتاج مراجعة شاشة شاشة (`TASchedules` lists، exam feedback، إلخ).

## 4) إدارة الاختبارات داخل الدفعة (حضور يوم الامتحان)

**المطلوب:** عند دخول المختبر على الدفعة في يوم الامتحان:
- لكل متدرب: **حاضر / غائب** لهذا اليوم.
- تسجيل نتيجة الامتحان **للحاضرين فقط**.
- اختيار **تاريخ** الامتحان عند الحاجة.

### الحالة في النظام الحالي
- الحضور اليومي موجود في `training_attendance` / الشبكة؛ **لا يوجد** ربط صريح «يوم امتحان الدفعة + حاضر فقط يُقبل له تقييم امتحان» في واجهة المختبر.
- **الفجوة:** نموذج بيانات يربط `(BatchID, ExamDate, CandidateID, Present)` أو استخدام `Attendance` بنوع جلسة «exam» + قيود على `talent_exam_feedback_evaluate`.

## 5) دور المبيعات / Salwa (الإغلاق)

### المهام
- متابعة من أنهى **اختبار تحديد المستوى** أو **النهائي (Exit)**.
- **Closer** يُقرأ من مسجّل الليد إن وُجد، وإلا إدخال يدوي.
- حقول المتابعة:
  - Follow Up Date  
  - Closer  
  - Language Feedback  
  - Closing Status  
  - Status Date  
  - Reason  

### Closing Status (قيم نهائية — بدون ترجمة عربية في العرض حسب المطلب)
- Confirmed Training  
- Pending Month  
- Not Interested  
- Rejected  
- Unreachable  
- Call Back  
- Pending  
- Reconsidering  
- Restrictions  
- GA Employee  
- Moved to Offshore  

### الحالة في النظام الحالي
- يوجد مسار مبيعات تدريب: Dashboard, Leads, Scheduling, Follow-up, Exam fee, Course fee — **بدون** شاشة موحّدة «TO BE CLOSE» وحقول الإغلاق أعلاه مربوطة بسير العمل.
- **الفجوة:** كيان/جدول أو أعمدة `Candidates`/`TrainingLeadPipeline` + واجهات + صلاحيات.

## 6) الحضور — ضيف (Guest)

**المطلوب:**
- سطر افتراضي/نوع **Guest** في حضور الحصة.
- زر **إضافة زائر** (عدة زوار): اسم، هاتف، بريد.
- من يدخل: المدرب، Cooperation، Salma (حسب الدور).

### الحالة في النظام الحالي
- لا يوجد تنفيذ لـ Guest في الحضور (بحث في الكود: لا سجلات ضيوف).
- **الفجوة:** جدول `ClassGuests` أو توسيع `Attendance` مع `EnrollmentID` اختياري + `IsGuest`.

## 9) الخلاصة المنطقية (المطلوب)

- مساران رئيسيان: **تدريب عادي** و **Train to Hire** — كلٌ له flow مختلف.  
- **مختبر المواهب (تدريب)** = نقطة تحويل رئيسية (أنواع اختبار + Status).  
- **المبيعات** = الإغلاق النهائي بعد نجاح المسارات المناسبة.  
- النظام يعتمد على: **`Status` + نوع الليد + نوع الاختبار**.

## 10) ملخص فجوات النظام الحالي (Place2026 Flask)

| المحور | موجود جزئياً؟ | ملاحظة |
|--------|----------------|--------|
| تسجيل ليد تدريب | نعم | حقول أقل من المطلوب؛ لا Train to Hire |

## 11) اقتراح مراحل التنفيذ (للمرجع — بدون التزام بتنفيذ فوري)

1. **نموذج بيانات:** أعمدة/جداول لليد (نوع، مستندات)، ربط دفع الامتحان بالحجز، توسيع تقييم المختبر.  
2. **قواعد الحجز:** منع `training_sales_book_slot` لـ Interested بدون دفع؛ استثناء Train to Hire بعد اكتمال الروابط.  
3. **واجهة المختبر:** أزرار أنواع الاختبار + Status كامل + قوائم مفلترة.  
4. **المبيعات:** شاشة TO BE CLOSE + Acceptance Train to Hire + صلاحيات.  
5. **الدفعة:** حضور جلسة امتحان + تقييم مشروط.  
6. **الضيوف:** جدول/نموذج إدخال.  
7. **التقارير:** الجدولان + فلاتر التاريخ.
