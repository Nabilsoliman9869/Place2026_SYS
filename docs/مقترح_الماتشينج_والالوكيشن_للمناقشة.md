# مقترح الماتشينج والالوكيشن — للمناقشة

**الغرض:** توثيق سير العمل المقترح للمطابقة (Matching) والترشيح (Allocation) وفتحه للمراجعة والمناقشة قبل التنفيذ.

---

## 1. الماتشينج (Matching) — المفهوم والهدف

**الهدف:** التدقيق على طلب عميل معين — هل لدينا في قاعدة البيانات مرشحون يتطابقون مع المتطلبات؟

**الحقيقة:** لن يكون هناك تطابق كامل ١٠٠٪ — بل تطابق جزئي عبر فلاتر.

### مثال طلب عميل
| المعيار | القيمة |
|---------|--------|
| العدد | 20 موظف |
| مستوى اللغة | B1 |
| معرفة بالحاسب | متوسط |
| النوع | ذكر |
| المؤهل | متخرج |
| المنطقة | القاهرة |
| العمر | 25–30 سنة |

### آلية الماتشينج
- **فلتر النوع** → كل الذكور المطابقين للطلب
- **فلتر اللغة** → B1 أو أعلى (مثلاً B2، C1)
- **فلتر المنطقة** → القاهرة أو كل المناطق
- **فلاتر إضافية** حسب توفرها في قاعدة البيانات

---

## 2. الشاشة المقترحة: Matching (منعزلة)

**الصلاحيات:** Allocator، Allocation Specialist، Allocation Manager، Account Manager

### الخطوات
1. **اختيار العميل** — من قائمة العملاء
2. **عرض طلبات العميل** — كل الـ Job Orders لهذا العميل
3. **اختيار طلب العميل** — طلب محدد (مثلاً: 20 موظف، B1...)
4. **عرض بيانات الطلب + أزرار فلاتر** — معايير الطلب واضحة
5. **جلب المرشحين** — استعلام على قاعدة البيانات حسب الفلاتر
6. **زر على مستوى السطر:** «الوكيشن» أو «ترشيح» — إرسال المرشح للترشيح

---

## 3. Allocation — شيت الريكروتر

**المحتوى:** كل المرشحين المختارين (المُترشَحين) يظهرون في شيت خاص بالريكروتر.

### حقول الشيت (لكل ترشيح)
| الحقل | الوصف |
|-------|--------|
| تحديد موعد مع المسؤول لدى العميل | موعد المقابلة |
| فيدباك الشخص | مسؤول التوظيف لدى العميل |
| الموعد المحدد | التاريخ والوقت |
| اشتراطات أخرى | متطلبات إضافية |
| المستندات المطلوبة مع المرشح | قائمة المستندات |
| ملاحظات | نص حر |

**اسم الشيت:** عميل + رقم الطلب + اسم المرشح (+ Allocator/Allocation Manager...)

### زر على مستوى السطر: اتصال بالمرشح
- يفتح: موعد الاتصال، ملاحظة، تأكيد المرشح بالعلم
- المعنى: الريكروتر اتصل بالمرشح وأكّد الموعد والمستندات
- بعد التأكيد → انتقال إلى تاب آخر

---

## 4. تاب المتابعة — الكاجندة

**تاب ثان:** كاجندة لمتابعة مقابلة مسؤول توظيف العميل مع المرشح والنتيجة.

**من يفتحه:** الريكروتر + كل مستويات الالوكيشن

### أزرار على مستوى السطر
| الزر | الوظيفة |
|------|----------|
| **ملاحظة** | أي مستخدم يسجّل ملاحظة — يُسجَّل المستخدم تلقائياً بجانب الملاحظة |
| **الفيدباك النهائي من العميل** | مقبول / مرفوض / Waiting List |

### عند «مرفوض»
- المرشح يعود ويظهر في **الماتشينج** لعملاء آخرين (يمكن ترشيحه لطلبات جديدة)

---

## 5. مقارنة سريعة مع النظام الحالي

| العنصر | النظام الحالي | المقترح |
|--------|----------------|----------|
| Matching | شاشة واحدة تجمع Job Orders + مرشحين جاهزين | شاشة منفصلة: عميل → طلب → فلاتر → مرشحون → ترشيح |
| الفلاتر | محدودة أو يدوية | فلاتر تفاعلية حسب معايير الطلب |
| الترشيح | Confirm Match → جدولة مقابلة | زر ترشيح على مستوى السطر |
| متابعة الريكروتر | صفحات متفرقة | شيت موحد للريكروتر مع كل البيانات |
| اتصال المرشح | غير موجود كنظام | زر اتصال + تأكيد المرشح |
| الفيدباك النهائي | Accepted/Rejected | مقبول / مرفوض / Waiting List |
| المرفوض يعود للماتشينج | غير مؤكد | صريح: يعود لعمليات ماتشينج جديدة |

## 6. نقاط للمناقشة

### أ) قاعدة البيانات
- هل الجداول الحالية (Candidates، ClientRequests، Matches، JobOrders...) تحتوي على كل المعايير المطلوبة؟
- ما الحقول الناقصة؟ (مثلاً: المنطقة، العمر، الجنس، المؤهل، مستوى الحاسب...)
- هل نحتاج جداول أو أعمدة جديدة لدعم الفلاتر؟

### ب) تعريف «المرشح المطابق»
- هل B1 «وأعلى» معيار ثابت أم حسب الطلب؟
- هل العمر يُعامل كنطاق (مثلاً 25–30) أم قيمة واحدة؟
- هل «معرفة الحاسب» مخزنة في قاعدة البيانات؟ وفي أي جدول/حقل؟

### ج) الصلاحيات
- Account Manager: هل يدخل شاشة الماتشينج كاملة أم جزءاً منها؟
- الريكروتر: هل يرى فقط ترشيحات مرشحيه أم كل الترشيحات؟

### د) سير العمل
- هل التدفق: Matching → Allocation → شيت الريكروتر → تاب المتابعة → فيدباك نهائي؟
- هل توجد حالات وسطى (مثل: مرشح وعد ولكنه لم يؤكّد بعد)؟

### هـ) واجهة المستخدم
- هل Matching شاشة مستقلة تماماً كما وصفت؟
- هل شيت الريكروتر تبويبات (Tabs) أم صفحة واحدة طويلة؟

## 7. مراحل تنفيذ مقترحة (بعد الاتفاق)

1. **المرحلة 1:** تحديث/توسيع نموذج البيانات ليدعم الفلاتر (المنطقة، العمر، الجنس، المؤهل، مستوى الحاسب...).
2. **المرحلة 2:** شاشة Matching الجديدة (عميل → طلب → فلاتر → قائمة مرشحين → زر ترشيح).
3. **المرحلة 3:** شيت الريكروتر (ترشيحات + حقول الموعد والفيباك والمستندات).
4. **المرحلة 4:** زر اتصال بالمرشح وتأكيد الموعد.
5. **المرحلة 5:** تاب المتابعة + ملاحظات + فيدباك نهائي (مقبول/مرفوض/Waiting List).
6. **المرحلة 6:** إعادة المرشحين المرفوضين إلى قوائم Matching.

## 8. ما هو متوفر حالياً في قاعدة البيانات

### ClientRequests (طلبات العميل)
| الحقل | ملاحظة |
|-------|--------|
| JobTitle, NeededCount | متوفر |
| Gender, Location | متوفر |
| AgeFrom, AgeTo | متوفر |
| EnglishLevel | متوفر |
| ComputerLevel | متوفر |
| EducationLevel | متوفر |
| SoftSkills, Requirements | متوفر |
| Nationality, ShiftType, ExperienceYears | متوفر |

### Candidates (المرشحون)
| الحقل | ملاحظة |
|-------|--------|
| FullName, Phone, Email | متوفر |
| CurrentCEFR / EnglishLevel | متوفر (من Evaluations) |
| SoftSkills | متوفر |
| IsReadyForMatching | متوفر |
| Gender, Age, Location/Address | **يُرجى التحقق** — قد تحتاج إضافة |

### Matches (الترشيحات)
| الحقل | ملاحظة |
|-------|--------|
| CandidateID, RequestID, Status | متوفر |
| InterviewDate, AllocatorFeedback | متوفر |
| ContactConfirmed, CandidateNotes | **قد تحتاج إضافة** لزر اتصال المرشح |
